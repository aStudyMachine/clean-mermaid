# 渲染串行化：形状设置与 `mermaid.render` 同处一段

判断节点菱形的几何靠替换插件自带 mermaid 的 `shapes` 表实现，而形状处理器只能读到模块级变量
`decisionShapeSetting` —— mermaid 会把自定义配置键剥掉，这是唯一能递话的通道（依据见
`docs/obsidian-internals.md`）。

0.1.11 之前，这个变量在 `renderDiagram()` 里赋值后直接 `await mermaid.render()`。并发请求会互相覆盖：
后一个请求改掉全局值，前一个请求仍在渲染的节点就读到错的形状，而结果仍以它自己的缓存键写入 ——
之后命中该键的图会显示另一套菱形。

现在所有 mermaid 渲染都走 `createSerialQueue()`：**赋值与渲染在队列的同一段里完成**。缓存键
（含 `decisionShape`）在入队前算好，所以每个请求的结果与自己的键始终一致；队列在任务失败后继续，
一次渲染报错不会卡住后续图表。

## Consequences

- 同一份源码的并发请求仍不会合并（两个窗格同时首渲同一张图会跑两次）—— 那是独立的性能优化。
- 不要为了「并行更快」把队列去掉、或把赋值挪到队列外：mermaid 的 `render` 内部虽有自己的排队，
  但不覆盖我们的赋值。
- 单次清缓存、或跳过缓存写入，都不能纠正已经返回的错误 SVG；只有让赋值与渲染同处一段才是根因修复。
